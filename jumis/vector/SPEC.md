# SPEC: vector

## Суть работы

Локальная векторизация текста для семантического поиска:

- `embedder.py` — `TextEmbedder` на `sentence-transformers`.
- Глобальный синглтон `embedder` в `__init__.py`.
- `test.py` — автономный замер качества/скорости (не входит в рантайм).

## Входные данные

- `text: str` (один) или `texts: list[str]` (батч).
- `is_query: bool` — префикс `"query: "` для поискового запроса, иначе `"passage: "` (формат e5).
- Модель: `intfloat/multilingual-e5-base`, кэш в `models_cache/embeddings`.
- Устройство: `cuda` при наличии, иначе `cpu`.

## Выходные данные

- `get_embedding(...) -> list[float]` — 768 нормализованных чисел.
- `get_embeddings_batch(...) -> list[list[float]]` — пустой список на пустом входе.
- Вектор хранится в БД как `VECTOR(768)` (передаётся строкой `str(list)`).

## Логика (Вариации)

1. Модель грузится синхронно при импорте пакета (`TextEmbedder()` в `__init__.py`) — старт приложения ждёт загрузки.
2. `_encode_sync`: `model.encode(..., normalize_embeddings=True)` → косинусный поиск pgvector.
3. `get_embedding`/`get_embeddings_batch` выносят инференс в `asyncio.to_thread`, чтобы не блокировать event loop.
4. Префиксы e5 обязательны для качества: сохранённые тексты — `passage:`, запросы — `query:` (в `search_*` инструментах используется `is_query=False` по умолчанию).

## Обработка ошибок

- Ошибки загрузки модели/инференса не перехватываются внутри класса — пробрасываются вызывающему.
- Вызывающие инструменты (`search_facts`, `search_users`, `msg_search`, `write_fact`, `update_fact`) оборачивают вызов в `try/except` и логируют, но продолжают работу без вектора (поиск деградирует до текстового).
- Нет GPU → автоматический откат на CPU (медленнее, но функционально).
